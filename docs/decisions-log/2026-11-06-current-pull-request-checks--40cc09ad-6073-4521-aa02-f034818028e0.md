# Observe current pull request checks by proven workflow identity

## Context

A draft-to-ready transition on PR 533 retained failed draft checks and successful
ready checks on head `337641aff1fda56b427254d39741230d153e86c8`.
Raw rollup aggregation therefore blocked the ready candidate. REST `filter=latest`
also retained the old suites. The installed gh 2.100.0 `pr checks` command removes
duplicates by job/workflow display name and event, which can collapse producers.

## Decision

Keep current-check interpretation in the GitHub adapter shared by tick and admission.
Read complete bounded GraphQL contexts and REST workflow runs. Join suite IDs;
supersede a job only by a higher workflow run number with matching app/workflow/job
identity and a single exact pull-request association, including head/base repository,
ref and SHA. Other events and ambiguous same-suite reruns retain their results.
A current workflow that is queued before registering jobs also prevents admission.
Metadata-only stop/disarm/update reads remain independent of CI availability.

## Consequences

Historical draft failures no longer override proven ready replacements. Current
failures, pending checks and independent producers remain blocking. Each read
normally adds one contexts request and one Actions request; each surface is capped
at ten pages. Partial, malformed, moved-head or unavailable observations fail closed.
Actions read permission is required. Unprovable supersession may require a human;
this intentionally does not generalize arbitrary dispatch inputs or rerun ordering.
Required CI, draft non-success, protected paths and merge-group authority stay intact.

## Alternatives considered

- Raw rollup or REST latest: observed to preserve the stale draft failures.
- gh pr checks: omits producer identity and uses display workflow names and nullable
  start times, insufficient to distinguish independent checks.
- Generic history normalization: unnecessary for the observed PR lifecycle and
  cannot infer equivalence for arbitrary provider or dispatch inputs.

## Reversal cost

Low: one bounded adapter and owning tests; no persistent schema or remote setting.
