# Native model choice owned by orchestration

## Context

The maintainer explicitly authorized DEV-1110 to adapt the approved frugality policy
to current native runtimes; this record accompanies that implementation for merge. The older
DEV-404 decision describes a removed workflow's `workerTier()` and commercial tiers;
keeping it as current routing guidance invents a capability consumers no longer have.
Available native controls differ, and requested identity does not prove effective identity.

## Decision

Keep model choice in `void-orchestrate`, using explicit user precedence, task risk and
current native controls, while preserving quality gates and the assigned writer.

Mechanical work may use a sufficient economical configured model; sensitive judgment
and independent review retain necessary capability. No fixed price/name ranking, provider
router, new configuration surface or version registry. Legacy authored-agent defaults
remain native defaults; canonical specialists retain inheritance and their budgets.
Application LLM API budgeting stays separate in `void-llm-cost-discipline`.

An unhonorable explicit choice stops its dependent launch. Without explicit selection,
unsupported controls use transparent inheritance/defaults. Diagnose unsupported settings;
reconcile uncertain starts before at most one confirmed-transient retry. Never silently
switch provider, permissions or user choice. Unknown effective model remains unknown.
DEV-863 owns detailed model/version observation.

## Consequences

Positive:

- One portable policy replaces obsolete routing claims without a new engine.
- Relevant advice and writer context survive; model cost does not waive quality.

Negative:

- Native limitations may prevent optimization or knowledge of the effective model.
- A user choice incompatible with required capability needs a surfaced decision.

## Alternatives considered

- Keep fixed commercial tiers and the retired workflow field: rejected because current
  runtimes do not share those identifiers, price assumptions or dispatch mechanics.
- Add a provider router and version registry: rejected as unnecessary duplication of
  native controls and DEV-863's separate observation responsibility.
- Restart existing writers to select cheaper models: rejected because it discards useful
  context and increases coordination instead of completing the accepted task.

## Reversal cost

Low: instructions and documentation only. No event/schema/configuration migration or
credentials changed; future selection can replace this policy through a superseding ADR.
