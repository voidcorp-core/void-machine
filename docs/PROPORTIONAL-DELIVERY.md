# Proportional delivery

The consumer outcome is time saved with reliable, maintainable code. The maintainer approved
this policy on 23 October 2026 after auditing the workflow; `void-implement` is its execution
owner. This document explains the policy rather than defining another controller.

| Domain | Required protection | Effort that does not repeat automatically |
| --- | --- | --- |
| Scope | Accepted behavior, real blockers and authority | Spec/plan/ticket formatting and approvals already given |
| Expertise | Detect changed coding domain; consult its primary specialist before production edits | All-specialist panels and unchanged advice |
| Tests | Observed failing test before behavior, then GREEN; relevant invariants/errors/boundaries | Separate phase commits, universal coverage percentage and duplicate assertions |
| Architecture | KISS, SOLID, explicit useful boundaries and types | Layers, abstractions or ADRs for routine reversible choices |
| UI | Affected states, keyboard/touch, mobile and desktop | Whole-app audit for a local edit |
| Integration | Changed journey proved at the appropriate boundary | Another E2E test when current evidence already proves that contract |
| Security | Safe inputs, auth/tenancy, secrets and side effects during development | Full deep audit per ticket; a final audit never replaces local safety |
| Review | One independent exact-subject review; concrete blockers resolved | Nit-driven corrections or another general review after each fix |
| Verification | Fresh affected proofs and all configured required CI | Unaffected tests rerun solely because unrelated prose changed |
| Reporting | Result, actual evidence and material limits | Twelve N/A checklist rows and a ledger of discarded preferences |

The smallest domain expert set is normally one. Add an expert for a different risk the primary
cannot cover. `void-orchestrate` owns the invocation; no new panel quorum or mission ledger is
created just to count advice. Missing consultation cannot be invented or described as complete.
Autopilot inherits these applicability decisions; entering its loop adds no preparation panel.
Keep the assigned writer and reuse relevant advice while its scope and inputs remain valid.
Tiny direct work and substantive native delegation follow the existing `void-orchestrate` policy.

Stop when acceptance, applicable proofs and independent review hold. A new concrete defect
receives the existing bounded targeted correction cycle. An optional improvement does not.
Configured coverage, CI, security hooks and authorization limits remain binding.

## Evidence and runtime limits

Installed, applicable, invoked and passed are distinct claims. A SKILL.md read does not establish
compliance, a test file does not establish TDD, and an arbitrary failing command is not RED.
Retain the actual relevant test command/result before implementation and GREEN afterward.

A different supported reviewer runtime is preferred for perspective. Current canonical mission
dispatch still authenticates the coordinator runtime; the preference does not change that source
binding or permit foreign completion receipts. A real independent review outside that dispatch
must retain its actual provenance and limitations, never pretend to be a canonical receipt.

## Deliberately subsequent work

The follow-up described in [TICKET-USAGE.md](TICKET-USAGE.md) reuses the existing cheatsheet and adds a
per-ticket recap of actual skills, hooks and specialists used, including unobservable states.
That tracking work was deliberately delivered separately from the workflow correction. No Langfuse
integration, event schema change, new dashboard or external transcript export is introduced.

Consumer measurements should compare elapsed delivery time, human interruptions, useful defects
found and escaped regressions on comparable tasks. Reading fewer instructions is not alone proof
of faster or better delivery. No productivity percentage is claimed by this policy.
