# DEV-1408: native targeted CI

Implements L8's approved CI decisions in the 23 November simplification plan.
No GitHub protection, installed root floor, main promotion or publication changed.
The coordinator owns independent review, remote three-OS runs and merge-group proof.

## Delivery and retained protection

- Ordinary YAML replaces the generator and per-gate JSON round trip together.
  Four cheap independent outcomes collect errors; the native barrier requires each
  applicable outcome to be successful. `validate` rejects every non-success producer
  result. Failed build prevents dependents. There are no retries or suite bail flags.
- Local `verify` keeps selection, command execution, artifact repair and optional exact
  HEAD assertion. It stops dependent work on failure. `derive:check` already covers
  hook and asset freshness; duplicate standalone checks no longer run in full verify.
- Git name-status retains both rename paths, detects deletion and broadens incomplete
  input. No changed-files API, pagination shortcut, graph, dependency or scheduler was
  added. Existing Vitest projects are selected for test-only edits. Pure engine policy
  leaves retain all dependent projects; platform-sensitive or uncertain work stays full.
- Three explicit native OS jobs preserve actual required context names, even when not
  applicable. YAML anchors share their steps. A skipped job is not an executed test.
  Main PRs validate the current combined merge SHA with all projects/OS; develop PRs
  validate head, and queue groups use their own combined SHA/base. PR base retargeting
  now triggers validation. Draft admission, human readiness and main auto-merge refusal
  remain. Only obsolete PR runs share cancellation.
- The DEV-1143 artifact producer remains the freshness owner before lifecycle generation.
  One tarball is inspected and consumed with its SHA/name/version/digest/run identity.
  Historical-release recovery and its distinct old-producer fixture remain unchanged.
- The residual five-line pre-commit and root prepare auto-configuration are retired.
  No Git configuration, personal hook or shared state was changed by the writer.
- Consumer enforcement remains a versioned pinned implementation; installed references
  support native additive jobs. Neither install/update nor a SHA pin guarantees caller
  invocation or remote required-check protection. Documentation now states that limit;
  the action description no longer claims unconditional bypass prevention.
- The control-character diagnostic no longer refers to retired project indexing.
  Its byte rules and negative controls are unchanged; source owns both shipped bundles.
