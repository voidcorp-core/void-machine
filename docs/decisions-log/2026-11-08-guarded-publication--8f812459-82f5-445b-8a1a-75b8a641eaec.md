# Couple publication to the shared Git guard

## Context

DEV-1204 reproduced a false refusal when Git generated regular `info/refs`.
The coordinator then pushed in a separate call despite the guard's exit 2.
An aggregate v3 digest cannot reveal which old info entry contributed to it.

## Decision

Couple the shared-state check and literal-SHA push in one coordinator command;
retain human renewal as an immutable record linked to its predecessor's digest.
Policy v4 excludes only regular root `info/refs`. Keep sensitive files and every
other protected category. Renewal names the candidate branch/SHA, observed new
digest, prior record digest, cause and human decision reference. It changes no
merge permission. Serialize supported publication and renewal per ticket.

## Consequences

A refused or unreadable guard launches no push. Identical renewal replay is
idempotent; stale, conflicting or incomplete evidence refuses. Original evidence
survives. Legacy v3 requires a fresh, explicit human decision, never conversion.
A process crash can leave a lock for human inspection. Direct Git and external
writers do not honor that lock; the command makes no repository-wide atomicity
claim. Failed transport needs remote inspection before a deliberate retry.

## Alternatives considered

- A check followed by an independent push retains the observed orchestration gap.
- A pre-push hook changes consumer hook wiring and still needs a reliable ticket
  association; this ticket instead repairs the explicitly supported CLI path.
- Replacing the baseline destroys the original proof; a separate mutable pointer
  and journal introduce a partial-update state the immutable linked record avoids.

## Reversal cost

Medium: preserve the v3/v4 evidence and renewal history when replacing the
operator path. The command uses Git's existing refspec and hook behavior, with
no new runtime dependency or consumer configuration.
