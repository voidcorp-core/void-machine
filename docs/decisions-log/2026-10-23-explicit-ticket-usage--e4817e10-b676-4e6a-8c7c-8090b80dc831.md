# Report only explicitly linked ticket usage

## Context

Users need the catalogue and actual ticket usage without another service or delivery loop.
Native telemetry and canonical ticket missions can have different IDs; timestamps cannot
prove their relationship. Codex skill-file loads do not prove native skill activation.

## Decision

Project existing explicitly linked events into one informational ticket-end usage recap, with
unknown coverage visible and the existing catalogue retained as the complete inventory.

## Consequences

Positive:

- Local, read-only inspection reuses existing receipts, parsers and catalogue declarations.
- Starts, outcomes, runtime provenance and missing linkage remain distinct.

Negative:

- Historical native sessions cannot be attributed to a ticket without an explicit binding.
- Missing instrumentation remains unknown and cannot certify compliance or quality.

## Alternatives considered

- External tracing platform: rejected by the user for this task; unnecessary service and data flow.
- Infer sessions from times/titles: rejected because correlation would invent ticket attribution.
- Mandatory telemetry gate: rejected because observability gaps do not establish a coding defect.

## Reversal cost

Low: an additive CLI report and skill instruction; no journal schema or runtime engine migration.
